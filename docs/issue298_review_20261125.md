## 已实施修复及证据

1. ARGMAX/ARGMIN 保留 FP16/FP32 输入，将结果及独立参考比较改为 U32；用非恒定数据检查索引。列 ARG 另保留源形状大小的物理载体、有效形状仍为 1×N，消除本机 lowering 的 SizeCode/geometry 错误。8 个配置全部构建通过。普通 TCOLMAX 控制构建通过。
2. Local MX ScaleA/ScaleB 改 CUBE_M32；ScaleB 有效形状为 N×ceil(K/group)。GEMV scale 保持 Vec role，避免与 Left 数据输入重载混淆。16 个 fixp 配置全部重编通过。单 PE MXFP4 的外部 B scale [groups,N] 用显式 GM stride 转为 [N,groups]，该配置构建通过；这只解决接口首错，不宣称 #199 的完整数值正确性已验证。
3. 三个 Bias 用例使用 accumulator dtype 的 CUBE_N8 [1,N]，以 TLOAD_CUBE 加载；全部构建通过。
4. FA fixpipe RowMax 改为最终 D 的 dtype/layout；6 个 FP8/MXFP4 配置通过。FP16 GroupMax 的本地/Shared 两个用例同步改成 FP16，通过。撤销旧注释中将非法辅助类型误归为模型缺陷的说法。
5. FP32 位模式 CAS 改用 U32 GM/Tile 载体，保留正负号和 payload 位，参考检查做逐位比较；不在计时区插入额外 FP32/U32 数据复制。构建通过。
6. 默认 TESTCASE=transpose 虽已迁出 TTRANS，仍请求 64 行 CellReg；拆成两段 32 行，保留 64×64 工作量，res_check=on 构建通过。
7. hosted 模式只由 adapter 提供 _start，旧汇编入口仅用于 baremetal。gather_v2/view_copy 的六个原配置链接通过；hash 按原清单 res_check=off 重测确认旧版重复入口、修复后通过；一个带完整参数的 baremetal gather 控制构建通过。
8. QSMLA 编译器路径与逐项 --compiler-arg 分离。旧脚本实测拒绝附加选项；五个新构建通过，另有 4 个主机单元测试覆盖带空格路径、argv、前缀读取、精确长度和短输入拒绝。

## 尚未实现的语义

- HiF4 FA 需要完整的 Matrix-MX U32 scale 输入/量化流程；现有三个驱动没有 scale ABI，不能仅将 USE_MX=1 或换 dtype。现明确提前报错并从正常精度 sweep 排除。不能将这 9 项计入修复通过数。
- S8 最终 D 不能请求 Matrix RowMax。保留两个编译负例，移出 active sweep/coverage；若需同时得到 S8 与 RowMax，必须明确定义浮点归约与后续量化的多阶段算法。
- HiF4 L1 量化仍失败：本机首先报 TCVT 的 capacity-derived rows 不一致；原 issue 的其他 SDK 首先报 physical columns。二者均不能通过调宽载体就证明 HiF4 standalone 转换合法。该项保持开放。
