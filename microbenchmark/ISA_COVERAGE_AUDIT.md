# Microbenchmark PTO ISA / TileOP API Coverage Audit

Audit date: 2026-09-08

## Reference baseline

- PTO specification: `pto-spec` `main@dea0b75e803c`, release `0.58.6`, ABI
  `pto-isa-0.58.6-mode-function-v1`.
- PTO operation catalog: `spec/catalog/tile-operations.json` (117 named Tile
  operations: 77 TEPL, 28 TLSU, 12 CUBE).
- TileOP source: `Linx-TileOP-API` `linx@b8669ce925a9`.
- Installed API/compiler used for validation:
  `linx-toolchain-build/output/linx_blockisa_llvm_musl`, clang 15.0.4
  (`linx64v5-musl-local 553b08045111`, target
  `linx64v5-unknown-linux-musl`).

The PTO catalog is authoritative for whether a name is current. The installed
TileOP header is used only to decide whether a current operation has a callable
C++ interface. This distinction matters because the current header still keeps
compatibility stubs/wrappers for retired names.

## Removed stale cases

The following names are in the PTO 0.58.6 `deleted_names` list and must not be
reported as active ISA coverage:

- `TCONCAT`
- `TPARTADD`
- `TPARTMAX`
- `TPARTMIN`
- `TPARTMUL`

Their 10 generated FP16/FP32 sources and build-list entries were removed. The
installed TileOP header still exposes these names as compatibility interfaces;
that does not make them current PTO operations.

## Added or restored coverage

New generated cases cover the previously omitted current operations:

- TEPL arithmetic/control: `TFMA`, `TSEL`, `TSELS`, `TTRI`.
- TEPL reductions: all row/column `SUM/MAX/MIN/PROD` and
  `ARGMAX/ARGMIN` forms, with distinct `M x 1` and `1 x N` destination
  descriptors.
- TEPL Tile-local data movement: `TGATHER`, `TSCATTER` with U16 index
  Tiles.
- PTO 0.58.5 layout/rearrangement: `TPERMUTE`, `TSHUF`, `TPACK`,
  `TUNPACK`, `TGPR2T`, using the required `CUBE_M16` carriers and control/index
  dtypes.
- TLSU: `TPREFETCH`, `MGATHER_CAS`, `GMOV`.
- Standalone TLSU command form: `BSTART.TIMG2COL`, covered by a
  microbenchmark-local inline-assembly wrapper and an FP32 1x1/no-padding
  numerical case. This is separate from the 117-name Tile operation catalog;
  the retired TEPL selector `0x064` is not used.
- Previously suppressed cases revalidated successfully with the current
  compiler: `TCMP`, `TCMPS`, `TMOV`, `MGATHER_MASK`, `MSCATTER_MASK`.
- CUBE accounting now maps the existing fixp modes to their actual formal
  operation names. The fixp suite already exercises all 12 `TMATMUL*` and
  `TGEMV*` names, so duplicate direct sources were not added.

`TSEL` was also corrected to the current three-operand in/out form:
`TSEL(dst, packed_predicate, src_true)`. Its predicate is generated by `TCMP`;
it is not modeled as an ordinary U16 data Tile.

## Remaining gaps

There are no uninventoried PTO 0.58.6 operation names. At operation level:

- 99/117 operations have active TileOP microbenchmark coverage.
- 18/117 are explicitly unsupported because the installed TileOP API has no
  named wrapper yet: `MGATHER_{EXCH,MAX,MIN,ADD,INC,DEC,AND,OR,XOR}` and
  `MSCATTER_{MAX,MIN,ADD,INC,DEC,AND,OR,XOR,POPC}`.

These 18 operations exist in the newer PTO 0.58.6 catalog but not in the
installed TileOP named-function surface. They should be moved from
`unsupported` to active tests when those APIs are published.

The resulting corpus contains 454 active configurations: 170 vector, 27
memory, 11 direct CUBE, 124 scalar, and 122 fixp.

One dtype-specific compiler limitation remains: `TABS<BF16>` crashes during
instruction selection. `TABS<FP16>` and `TABS<FP32>` stay active, so this does
not constitute an operation-name coverage gap.

## Compile validation

All generated TEPL and TLSU cases were compiled and disassembled with the
compiler baseline above, with build products redirected to `/tmp`:

- vector: 170/170 active cases passed;
- memory: 27/27 active cases compiled and disassembled, including
  `BSTART.TIMG2COL`;
- excluded probe: `tabs_bf16_16x16` reproduced the known clang instruction-
  selection crash and remains an explicit unsupported variant.

The new TEPL selectors are present in the disassembly with the PTO-specified
selector values (`117..120` for `TPERMUTE/TSHUF/TPACK/TUNPACK` and `126` for
`TGPR2T`). The current `llvm-objdump` mnemonic table has not caught up: it
prints the first four numerically and decodes selector 126 as the legacy name
`ESAVE`. This is a disassembler-label lag, not missing code generation.

This validation is compile/disassembly coverage. It does not claim functional
model support or numerical correctness for the newly added instructions.

For `timg2col_fp32_64x8`, llvm `553b08045` does not yet parse the standalone
`BSTART.TIMG2COL` mnemonic and incorrectly restricts the required
`ND2M16/ND2M32` layout selectors to TLOAD/TSTORE. The local wrapper therefore
emits the PTO-defined BSTART and B.DATR words directly; `llvm-objdump` confirms
`BSTART.TLSU 28, FP32`, `B.DATR ND2M16.normal, Zero`, all three dimensions,
the two contiguous B.IOR records, and a 512-byte Local destination per PE.
The required four-PE run uses one shared static GM source, distributes 64 group
rows as four 16-row M16 slices, and stores the slices to disjoint GM ranges.
gfrun `9d4464dc` completes all four PEs and returns `R2 = 0` against the exact
1x1/no-padding identity oracle. The remaining limitation is the compiler
assembler/disassembler surface, not the encoded operation or model execution.
