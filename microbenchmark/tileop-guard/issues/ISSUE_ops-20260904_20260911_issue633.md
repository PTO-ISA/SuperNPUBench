## 现象

col-reduce（TCOLMAX 等）的**直接输出**（不经任何 elementwise op，如 TCVT/TABS/TSEL/COPY）作为 TSTORE 源，
当该输出 tile 的 **valid col < physical col（列 boxed，如 physical 64 / valid 40）** 时，gfrun 执行期崩：
```
ASSERTION FAILED: inst->srcs.size() == 2 && inst->dsts.empty() &&
  IsLegalLocalTileDescriptor(inst->srcs[1]) && "Local TSTORE requires one legal source Tile descriptor"
```

**demo 写法**（`sfu/src/tcolmax_boxcol.cpp`）：
```cpp
using SrcTile = Tile<Location::Vec, float, M, 64, RowMajor, M, 40>;  // 物理 M×64 valid M×40
using OutTile = Tile<Location::Vec, float, 1, 64, RowMajor, 1, 40>;  // 物理 1×64 valid 1×40 (列 boxed)
TLOAD(tA, a0);
TCOLMAX(tC, tA);      // col-reduce 直接输出 (valid col 40 < physical 64)
TSTORE(c0, tC);       // 直接 TSTORE, 无中间 elementwise op → 崩
```

**约束与对照（已实测）**：
- API static_assert（`template_asm.hpp`）要求 **`dst.Cols==src.Cols` 且 `dst.ValidCol==src.ValidCol`**——故源与
  目的必须同为 physical 64 / valid 40 才能构造 boxed 场景（源非 boxed 时编译即失败：`TCOLMAX destination
  columns must match the source columns`）。
- **非 boxed（physical==valid，64/64）直接 TSTORE → PASS**。
- boxed 输出**中间插 TABS 再 TSTORE → 也崩**（`"unary TEPL source dtype/shape/stride is incompatible"`；
  TABS 亦拒该 boxed-col col-reduce 输出）。即问题**特定于 valid col < physical col 的 col-reduce 输出描述符**。

## Spec 对照：第一偏离点在模型 col-reduce 描述符 stamp

**① Demo 合规**：boxed tile（valid 40 < physical 64）是标准带 padding 的 tile；`pto-spec`
`asl/tile/reduce-and-expand/column-reduction/TCOLMAX.asl` legality 明文：
> "The destination has logical ValidRow equal to one and ValidCol equal to source.ValidCol; **its physical
> geometry is derived from the selected layout and capacity**."

即目的**物理几何由 layout+capacity 派生**——1×64 tile 容量 256B ⇒ 物理 col=64、valid col=40。API static_assert
亦放行。故构造 spec-legal。

**② 模型不合规（第一偏离点）**：`isa/Block.cpp` colReduce 支（`if (colReduce)`，约 L2692）：
```cpp
if (colReduce) {                         // colReduce 覆盖 TCOLMAX/SUM/MIN/PROD/ARGMAX/ARGMIN (L2443)
    dst->tileInfo->validCol = validCol;  // 40
    dst->tileInfo->validRow = 1;
    dst->tileInfo->col = validCol;       // ← 物理 col 塌成 valid col (40)，违反 "physical derived from capacity"
    dst->tileInfo->row = dst->size / (validCol * elemBytes);
}
```
tile 实际分配 `size=256`（物理 1×64），但此处把 `col=40`，二者矛盾。下游
`emulator/engine/AccumulateBlockInfo.cpp::IsLegalLocalTileDescriptor`（RowMajor 支）要求
**`source->size == rows × col × elementBytes`** = 1×40×4 = **160 ≠ 256** → 判非法 → TSTORE 崩。

**③ 对照 row-reduce 支**（同文件约 L2679）——**正确处理了 padding**（注释明写）：
> "The allocation may include padding, but **PTO does not define that spare capacity as additional physical
> Tile geometry**."
> `dst->col = stride(1); dst->row = dst->size / (stride*bytes);`（从 size 派生几何，吸收 padding，保持一致）

即 **row-reduce 从 size 派生几何保持一致，col-reduce 却硬把 `col=validCol`**——非 boxed 时 `validCol==physical`
恰好一致（故 PASS），boxed 时（valid<physical）就与分配 size 矛盾（故崩）。

**数值**：OutTile 物理 1×64 float ⇒ `size=256B`；col-reduce stamp `col=40` ⇒ `storageBytes=1×40×4=160`；
`256 ≠ 160` ⇒ `IsLegalLocalTileDescriptor` 失败。

## 涉及范围

模型 `colReduce` 判定（`isa/Block.cpp:2443`）覆盖 **TCOLMAX / TCOLSUM / TCOLMIN / TCOLPROD / TCOLARGMAX /
TCOLARGMIN** 全部——均走该 `col=validCol` 支，故**列归约全族**在 boxed 输出直接 TSTORE 时同崩。

## 建议

col-reduce 支应像 row-reduce 支一样**从分配 capacity 派生物理 `col`**（如 `dst->col = dst->size /
(rows × elemBytes)` 得 64），`validCol` 仍 = source.ValidCol（40），使描述符自洽（`size == rows×col×bytes`），
与 `TCOLMAX.asl` "physical derived from capacity" 一致；boxed 输出即可直接 TSTORE。

## 看护落点

- `sfu/tcolmax_boxcol`（col-reduce boxed 输出直接 TSTORE，物理 64/valid 40）→ **run-fail witness**。
  golden 已就绪（`fam='reduce' op='max' foot='col' VN=40`：校前 VN=40 列列 max，物理 padding [VN:64] 不校）；
  模型修好后自动转精度校验。全族其余成员（TCOLSUM/MIN/PROD/ARGMAX/ARGMIN）共用同一 colReduce 支，可按需补齐。
