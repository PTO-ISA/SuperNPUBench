## 本轮自证为真的模型/工具链缺口（已挂 issue）

### 1. B.FPATR None —— CUBE matmul 全族 + FIXP float 输出族（10 run-fail）
`ASSERTION FAILED: preQuantMode!=0 || (rMode==FRM_NONE && !saturation)` @ `AccumulateBlockInfo.cpp:1109`。
header 对非量化（float 累加）路径硬编码 `B.DATR …, RNE, NOSAT`，model 要求 PreQuant=0 时 RMode=NONE。
- CUBE：tgemv / tmatmul / tmatmul_acc / tmatmul_bias / tmatmul_mx / tmatmul_rowmax
- FIXP：chain / cscale / group_max / rowmax_acc
- **铁证**：release 自带 `microbenchmark/cube/src/*`（带 `verify()` 数值校验）与 `microbenchmark/fixp/src/fixp_tmatmul.cpp`
  用当前工具链**现编全崩同一断言**；预编 ELF 陈旧（旧 header 发 NONE）故假 PASS。量化/relu（PreQuant≠0）路径正常
  （tmatmul_f16 / tmatmul_relu / convert / prelu 均 PASS）。→ ISSUE_gfrun_ops20260904_model_gaps.md §1

### 2. 行/列归约 header↔model 维度 skew（6 run-fail + 5 精度失败）
header TROW*/TCOL* 静态-valid 源走 Branch-1，把 **dst** 的 valid 维度发进 `lb0/lb1/lb2`，model 按**源**归约几何解码。
- 行 run-fail：trowmax / trowmin / trowsum / trowprod / trowargmax / trowargmin
  —— `PTO v0.58 row reduction requires final compatible source and destination descriptors` @ `Block.cpp:1817`
- 列精度失败：tcolmax / tcolmin / tcolsum / tcolprod / tcolargmax（out==输入 row0，model 只归约 lb1=1 行）
  —— tcolargmin 恰好 PASS（真 argmin 落 row0 巧合）
- **铁证**：release 自带预编 `reducemax_row …int32_t_tM16_tN128….elf`（官方参考 kernel `reducemax_rowvec.hpp` 编出）
  在当前 model 崩同一断言；demo 已改真 M×1 / 1×N dst（复刻 reducemax_{row,col}vec.hpp）。→ §2

### 3. TINVALID 保留/删除选择子 —— 0.58.5 layout 算子（4 run-fail）
tpack / tpermute / tshuf / tunpack：`illegal instruction: reserved/deleted tile selector` @ `SoftCore.cpp:930`
（model 解码器把选择子映射到 `TileOp::TINVALID`）。
- **自证**：header（f8fb894）暴露这些 0.58.5 intrinsic 且按 doc 签名可编译，编译器下译出合法 bundle，
  model 解码器不认该选择子 = 模型未实现。→ §3

### 4. tgpr2t 后端 Match Instruction Error（1 编译失败，工具链）
`template_asm.hpp:11077: error: Match Instruction Error!`——header 自身的 GPR2T bundle 无法被配套 LLVM 后端汇编。
- **自证**：demo 按 doc 签名调用，崩在 header 展开的内联汇编、LLVM 后端指令匹配阶段 = 工具链 header↔backend 缺口，
  非 demo 写法。→ ISSUE_linx_ops20260904_toolchain_gaps.md §1

## 本轮修正：mgather_cas 是我的 demo bug（已修 → PASS）

前轮记为「128/256 HIT CAS 漂移」精度失败 witness。本轮严格自证证伪：`-t2` 显示 lane(0,0) **执行 4 次**
（gfrun 跑 4 个 SPMD PE-thread，都对同一 backing GM 做非幂等 CAS），model 每次 CAS 都算对
（`old=Load(swap前)` 再 publish）。**根因是 demo 未做 4-PE leader-gate**，非 model bug。已加
`if (get_thread_idx()!=0) return 0;`（issue#489 idiom）→ **mgather_cas 现 PASS**。教训：非幂等原子/搬运类
demo 必须 leader-gate。
